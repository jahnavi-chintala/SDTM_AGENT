# Synthetic raw multi-vendor data: study ZVR210-201

**Test data only.** Every patient, site, investigator, drug and vendor here is fictional. The
files were generated by `scripts/raw_vendor/make_raw_vendor_data.py` and contain no real
patient data. Do not mix them with real study data.

## Why synthetic

Real raw vendor transfers (central lab, PK/ADA, imaging, IRT, eCOA, genomics, safety) are
never published. They are confidential under each vendor's data transfer agreement. Public
patient-level sources were checked:
- NIDA Data Share has CRF-level raw files, but downloads are paused while it moves to
  controlled access.
- Project Data Sphere, Vivli, YODA and CSDR need an approved application.
- pharmaverse and the CDISC pilot only release SDTM/ADaM.

So the package below is simulated. Each file follows its vendor type's usual raw layout.

## The study

ZVR210-201 is a fictional open-label Phase 2 study in first-line advanced triple-negative
breast cancer. It randomised 1:1:1 within permuted blocks, stratified by PD-L1 CPS (<10 vs
≥10) and prior taxane:

| Arm | Treatment |
|---|---|
| A (`ZV210`) | ZV-210 20 mg/kg IV Q3W (bispecific antibody) |
| B (`ZV210_ZK415`) | ZV-210 20 mg/kg + ZK-415 3 mg/kg IV Q3W (antibody-drug conjugate) |
| C (`PACLI`) | Paclitaxel 80 mg/m² IV Days 1, 8, 15 Q3W |

- **Subjects:** 58 screened (8 screen failures) and 50 randomised, at 8 sites in the USA,
  Spain, Germany, Japan and Australia.
- **Data cut-off:** 2026-09-15.

## One study, many vendors

Each folder is one vendor's transfer. The same patients, visits and samples run through all
of them, linked the way they are in real life: by accession number, sample barcode and
visit, not by a shared key.

- US, Japanese and Australian sites send initials, with `-` for no middle initial.
- German and Spanish sites send none: `---` at the lab, `PRIVACY` in the safety database.
- Those two sites record birth dates as year only: `UN UNK 1977` in EDC.

## Real-world mess, on purpose

The data contains the problems a data manager finds when reconciling vendors. All of them
are listed in `_answer_key/planted_discrepancies.csv`:
- a subject ID keyed with the letter O instead of zero
- lab samples recorded as collected in EDC but never received by the lab
- an SAE with no EDC SAE page, and an SAE that exists only in the safety database
- an IRT stratum that disagrees with EDC
- a trailing space in an eCOA subject ID
- corrected and cancelled lab results
- central imaging readers disagreeing with the investigator and with each other

## Answer key

`_answer_key/` is ground truth for testing. It would never come from a vendor.

- **`subject_id_crosswalk.csv`:** every vendor's ID for each patient, plus arm, status,
  dates and true best response.
- **`planted_discrepancies.csv`:** the deliberate issues listed above.
- **`study_design.csv`:** study ID, data cut-off and arms.

`MANIFEST.csv` lists every file with its vendor and row count.

## Regenerate

```bash
python scripts/raw_vendor/make_raw_vendor_data.py            # default seed 20260915
python scripts/raw_vendor/make_raw_vendor_data.py --seed 7   # a different, equally valid study
```

The same seed always gives byte-identical files. The generator uses only the standard
library.
